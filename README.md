# Drum Simulator

악보를 넣으면 3D 드러머가 실시간으로 연주하는 웹 드럼 시뮬레이터입니다.

**바로 써 보기: https://mynseo.github.io/DrumSimulator/**

## 이렇게 써요

1. 위쪽 ▶ 를 누르면 예제 곡을 연주합니다. 왼쪽 위 곡 이름을 눌러 다른 예제(록 비트, 셔플, 드럼 솔로 등)로 바꿀 수 있습니다.
2. **⋯ → 파일 열기**로 내 악보를 넣습니다.

   | 넣을 수 있는 것 | 하는 일 |
   | --- | --- |
   | **PDF 드럼 악보** (.pdf) | 악보 프로그램으로 만든 PDF를 읽어 반복·D.S.·코다까지 펼쳐 연주 (그림으로 된 스캔 PDF도 어림해서 읽음) |
   | **음원** (.mp3 .wav .m4a …) | 드럼 소리를 찾아 악보로 바꾸고 원곡과 함께 재생 |
   | **MIDI** (.mid) | GM 드럼 채널을 악보로 |
   | **드럼 탭** (.txt / 붙여넣기) | `HH|x-x-x-x-|` 같은 텍스트 악보 |
   | **JSON** (.json) | 이 앱에서 저장한 악보 |

3. PDF 악보를 열었다면 아래 **악보** 탭에서 악보를 그대로 보며 지금 치는 마디를 따라갈 수 있습니다. **편집** 탭의 칸을 눌러 직접 고치거나, **패드** 탭에서 직접 쳐 볼 수 있습니다. 칸 조작법은 **?** 버튼에 있습니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 단위 테스트 (손발 배정, 동작, 가져오기, 음원 분석, PDF 악보 등)
npm run build    # 타입 검사 + 배포용 빌드(dist/)
```

## 웹사이트 배포 (GitHub Pages)

`.github/workflows/deploy.yml`이 기본 브랜치에 push될 때마다 테스트 → 빌드 → GitHub Pages 배포를 자동으로 합니다.
다른 브랜치에 push하면 테스트와 빌드만 확인합니다.

처음 한 번만 저장소 설정이 필요합니다.

1. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
2. 비공개(private) 저장소는 GitHub Pro 이상에서만 Pages를 쓸 수 있습니다. 무료 계정이면 **Settings → General → Danger Zone** 에서 저장소를 공개(public)로 바꿔야 합니다.
3. **Actions** 탭에서 *Deploy to GitHub Pages* 를 다시 실행하거나 새로 push하면 `https://<사용자명>.github.io/DrumSimulator/` 에 사이트가 열립니다.

빌드 결과(`dist/`)는 상대 경로로 만들어지므로 Netlify, Vercel, Cloudflare Pages 같은 정적 호스팅에 그대로 올려도 됩니다.

## 단일 HTML 페이지로 빌드

```bash
npm run build:artifact   # dist-artifact/drum-simulator.html
```

앱 코드와 스타일을 HTML 한 파일에 넣고, three.js와 pdf.js는 jsDelivr CDN에서 불러옵니다.
claude.ai 아티팩트처럼 파일 다운로드가 막힌 곳에서는 "저장" 버튼이 악보 JSON을 클립보드에 복사합니다.

## 화면

- 위: 재생·정지, BPM(−/+), 소리·캐릭터·더보기(파일 열기, 드럼 탭, 저장, 마디, 박 나눔, 반복, 메트로놈)
- 가운데: 3D 무대. 왼쪽 위 곡 이름을 누르면 다른 곡으로 바꾸고, 오른쪽 아래에서 카메라(정면·옆·위·시점)를 고릅니다.
- 아래: 악보(PDF) / 편집 / 패드 전환, 패드에서는 녹음

## 지금 되는 것

- **3D 드럼 연주**: 드럼 세트(킥·스네어·탐 3개·하이햇·크래시 2개·라이드)와 드러머가 악보대로 연주합니다. 마우스로 돌려 보고, 정면·측면·위·드러머 시점으로 전환할 수 있습니다.
- **정확한 손발 배정**: 하이햇·라이드는 오른손, 동시에 치는 스네어는 왼손(크로스 핸드), 오른쪽 크래시·플로어 탐을 하이햇과 같이 치면 팔이 엇갈리지 않게 오른손이 오른쪽, 필인은 박마다 오른손이 오게 번갈아(박 사이에서 시작하면 왼손부터), 한 손으로 너무 빠른 연타는 손을 바꾸고 북을 한 손으로 세 번 연달아 치지 않습니다. 하이햇·라이드로 박을 타는 동안에는 사이의 스네어·탐을 왼손이 맡아 오른손이 박 자리에 남습니다.
  악보의 "크래시"는 상황에 맞는 쪽을 칩니다: 하이햇 대신 라이드로 박을 타는 구간과 필인이 끝난 직후는 오른쪽 크래시, 그 밖에는 왼쪽 크래시. 크래시를 이어 치는 구간은 한쪽으로 이어 치고, 오른손이 아직 필인을 마무리하느라 왼손이 칠 때는 팔이 엇갈리지 않게 왼쪽 크래시를 칩니다. 편집기의 "크래시 2" 줄에 직접 넣은 음이나 왼손으로 지정한 크래시는 그대로 둡니다. 킥은 오른발, 하이햇 페달은 왼발입니다. 편집기에서 우클릭(휴대폰은 길게 누르기)으로 손을 직접 지정할 수도 있습니다.
- **셈여림**: 고스트·보통·악센트가 소리와 동작 모두에서 확실히 다릅니다. 소리는 크기 차이(고스트↔보통 약 10dB, 보통↔악센트 약 4dB)에 더해
  고스트는 둔하게(고음을 깎고), 악센트는 밝게(고음을 올려) 냅니다. 드러머는 고스트를 헤드 바로 위에서 톡, 악센트는 높이 들었다가 내려치고,
  빛과 파문도 세기에 따라 크기·밝기가 달라집니다.
- **더블 스트로크**: 한 손씩 번갈아 치면 한 손 간격이 0.055초보다 짧아지는 빠른 롤은 RRLL 더블로 칩니다.
  둘째 타는 손목을 다시 들지 않고 낮게 튕겨 치며 조금 약하게 납니다. 손을 지정한 음이나 플램이 섞인 구간은 그대로 둡니다.
- **림샷**: 스틱이 헤드와 테를 함께 때리는 '딱' 소리. 드러머는 스네어 드러머 쪽 테를 칩니다.
  편집기 "림샷" 줄, 패드(G·H 키), 드럼 탭 스네어 줄의 `r`, MIDI 40번, PDF의 스네어 자리 동그라미 X로 넣습니다.
- **플램**: 다른 손이 약 30ms 먼저 약하게 치는 꾸밈음. 편집기에서 칸을 눌러 "세게" 다음 단계로 넣고(칸 왼쪽 위 작은 점),
  PDF 악보의 꾸밈음, 드럼 탭의 `f`, MIDI의 약-강 연타도 플램으로 읽습니다. 반대 손이 같은 순간 다른 것을 치고 있으면 꾸밈음은 생략합니다.
- **타격 피드백**: 맞은 부품이 친 손발의 색(오른손 주황, 왼손 파랑, 오른발 초록, 왼발 보라)으로 빛나고 파문이 퍼지며, 심벌은 흔들립니다. 오픈 하이햇이면 윗 심벌이 실제로 열리고 페달 발이 올라갑니다.
- **악보 입력**
  - **음원에서 드럼 뽑기**: 더보기 → 파일 열기에서 음원(mp3, wav, m4a 등)을 고르면 빠르기를 찾고 킥·스네어·하이햇·탐·크래시를 악보로 바꾼 뒤,
    원곡과 박을 맞춰 함께 틀어 줍니다(소리 → 원곡 볼륨). 서버 없이 브라우저 안에서만 처리하고 파일은 밖으로 나가지 않습니다.
    16분음표·셋잇단·16분 셋잇단·32분음표 중 곡에 맞는 격자를 스스로 고르고, 기타·보컬처럼 음높이가 이어지는 소리는
    타격음/지속음 분리(HPSS)로 걸러 냅니다. 그래도 베이스가 큰 곡에서는 베이스를 킥으로 착각하는 등 정확도가 떨어집니다.
    틀린 부분은 악보 편집기에서 고치면 됩니다. (유튜브 링크는 약관·저작권 문제로 지원하지 않습니다.)
  - 격자 편집기: 클릭으로 음 추가 → 악센트 → 고스트 → 삭제, 8분·셋잇단·16분·16분 셋잇단·32분음표 격자
  - **PDF 드럼 악보 불러오기**: 아래 [PDF 악보 읽기](#pdf-악보-읽기) 참고
  - **악보 보며 따라가기**: PDF를 열면 "악보" 탭에 PDF 페이지가 그대로 나오고, 연주 중인 마디에 상자, 지금 박 자리에 세로선이 움직입니다. 화면 밖으로 넘어가면 따라 내려가고, 마디를 누르면 그 마디로 이동합니다(반복으로 여러 번 치는 마디는 지금 위치 다음 차례로). PDF 그림은 저장하지 않아서 새로고침하면 PDF를 다시 열어야 보입니다.
  - **유튜브 원곡 함께 틀기**: 더보기 → 유튜브 원곡에 링크를 넣으면 영상이 화면 한쪽에 뜨고 재생·멈춤·이동·반복·빠르기를 악보에 맞춰 따라갑니다. 유튜브 소리는 페이지가 분석할 수 없어서, **맞추기**를 누른 뒤 악보 첫 박(또는 멈춰 둔 마디의 첫 박)이 들릴 때 **지금!**(Space)을 눌러 박을 맞춥니다. ◀ ▶로 0.05초씩 옮길 수 있고, 곡 이름별로 영상과 맞춘 자리를 기억합니다. 영상 속도는 유튜브가 허용하는 배속(0.25~2배)으로만 바뀌고, 다른 사이트 재생을 막아 둔 영상은 틀 수 없습니다.
  - MIDI 파일(.mid) 불러오기: General MIDI 드럼 맵, 템포·박자·박 나눔(셋잇단·32분음표 등) 자동 인식
  - 텍스트 드럼 탭 붙여넣기 / .txt 불러오기
  - JSON으로 저장·불러오기, 브라우저에 자동 저장
- **직접 연주**: 아래 "패드" 탭에서 패드를 터치(휴대폰)하거나 클릭, 또는 키보드로 칩니다. 드러머가 그 순간 그 드럼을 치고, 손은 실시간으로 정합니다(하이햇+스네어를 같이 치면 오른손·왼손, 빠른 연타는 번갈아). 패드 가운데를 칠수록 세게, 키보드는 Shift를 누르면 악센트입니다.

  | 키 | 악기 | 키 | 악기 |
  | --- | --- | --- | --- |
  | Q | 크래시 | A | 하이햇 열림 |
  | W | 하이 탐 | S · K | 하이햇 |
  | E | 미드 탐 | D · J | 스네어 |
  | R · I | 크래시 2 (오른쪽) | F · L | 플로어 탐 |
  | U | 라이드 | G · H | 림샷 |
  | B · N | 킥 | X | 하이햇 페달 |

  "녹음"을 켜면 반복 재생에 맞춰 친 음이 가장 가까운 칸에 맞춰 악보에 들어갑니다.
- **사운드 킷**: 위쪽 "소리"에서 고릅니다.
  - **어쿠스틱 (실제 녹음)**: 실제 드럼을 녹음한 샘플. 세기에 따라 다른 녹음(부드러운/단단한 음색)을 씁니다.
  - **기본 합성**, **808**(힙합·트랩), **일렉트로닉**(909 계열, 하우스·테크노), **8비트**(게임기 소리)
  - **내 샘플**: 내 오디오 파일(wav, mp3 등)을 악기마다 넣어 연주. 파일은 브라우저(IndexedDB)에만 저장됩니다.
- **캐릭터 교체**: 드러머 / 고양이 / 록커. 큰 머리와 점 눈의 단순한 캐릭터로, 눈을 깜빡이고 연주 중에는 박자에 맞춰 고개를 끄덕입니다.
  록커는 금발 장발을 한쪽으로 쫙 넘겨 한쪽 눈을 덮고 소리를 지르며, 박마다 좌우로 번갈아 크게 헤드뱅잉합니다.
  머리카락은 머리를 늦게 따라오는 스프링이라 세게 흔들수록 출렁입니다.
- **드럼 솔로**: 예제의 "드럼 솔로"(정해진 8마디)와 "드럼 솔로 (매번 새로 만들기)"(고를 때마다 새 솔로). 스네어 악센트·고스트, 탐 돌리기, 손발 섞기, 크래시 강조를 한 박 단위 조각으로 이어 붙이고, 사람이 칠 수 있는지(손 셋이 필요 없고 같은 손 연타가 너무 빠르지 않은지) 테스트로 확인합니다.

## PDF 악보 읽기

Finale·MuseScore·Sibelius 같은 악보 프로그램으로 만든 PDF(악보 사이트에서 받은 PDF 등)를 브라우저 안에서 읽습니다.
이런 PDF에는 음표가 그림이 아니라 **음악 글꼴의 글자**와 **선**으로 들어 있어서, 그 위치를 따라 악보를 다시 짭니다.

1. `pdfPage.ts`: pdf.js의 그리기 명령을 따라가며 글자 하나하나의 위치와 선분(오선·마디줄·기둥·빔)을 뽑습니다.
2. `sheet.ts`:
   - 같은 길이의 가로선 5개 = 오선, 타악기 음자리표(또는 X 음표)가 있는 오선 = 드럼 줄
   - 음표 머리 높이 → 악기, 기둥·빔·꼬리·점·셋잇단 숫자 → 길이, 꾸밈음(플램)은 박자에서 제외
   - 기둥이 위 = 손, 아래 = 발 성부. 성부마다 길이를 더해 박 위치를 구하고, 길이가 안 맞는 마디만 다른 성부의 위치로 맞춥니다.
   - 강세(>), 하이햇 열림/닫힘(o/+), "ride"·"Closed H.H" 글씨를 반영합니다.
   - 여러 마디 쉼표는 막대 위에 적힌 수만큼 빈 마디로 펼칩니다.
   - 마디 반복 기호: 한 마디 반복(•/•)은 바로 앞 마디를, 두 마디 반복(•//•, 두 마디 사이 마디줄 위)은 앞의 두 마디를 그대로 칩니다.
   - 곡 중간의 박자표(3/4, 6/8 …)를 만나면 그 마디부터 마디 길이를 바꿉니다. 편집기·메트로놈·재생 위치도 마디마다 다른 길이를 따릅니다.
   - 도돌이표, 1·2번 괄호, D.S./D.C., To Coda·코다, `<2x>`·`<D.S time>`처럼 반복 때 바뀌는 줄을 따라 연주 순서대로 펼칩니다.

| 오선 위치 | X 머리 | 일반 머리 |
| --- | --- | --- |
| 덧줄 위 (A5 이상) | 크래시 | — |
| 윗줄 위 칸 (G5) | 하이햇 (o 표시면 열림) | — |
| 맨 윗줄 (F5) | 라이드 | 하이 탐 |
| 넷째 칸 (E5) / 넷째 줄 (D5) | — | 하이 탐 / 미드 탐 |
| 셋째 칸 (C5) | 크로스 스틱 → 스네어 | 스네어 |
| 둘째 칸·가운데 줄 (A4·B4) | — | 플로어 탐 |
| 첫째 칸 이하 (F4) | — | 킥 |
| 아랫줄 아래 (D4) | 하이햇 페달 | 킥 |

**기호별 악기 지정** (더보기 → 기호별 악기): 출판사마다 클로즈·오픈 하이햇, 크래시, 라이드를 그리는 자리와 머리 모양이 달라서,
읽은 음마다 악보 기호(머리 모양 · 오선 자리 · o 표시 · ride 글씨)를 남겨 둡니다. 기호마다 악기를 고르면 그 기호의 음이 모두 바뀌고,
"앞으로 여는 PDF에도 이대로"를 켜 두면 다음에 여는 PDF에도 같은 지정을 적용합니다.

지원 글꼴: Finale Maestro / MaestroPercussion, SMuFL 글꼴(MuseScore의 Leland, Bravura 등).
음표 위·아래에 따로 적힌 R·L 스티킹 글자는 그 손으로 치고, 기둥에 그은 트레몰로 빗금은 음 길이 동안 잘게 쪼개 칩니다(빗금 수 + 빔 수만큼 짧은 음표).
MuseScore처럼 발 성부의 쉼표를 숨긴 악보는 손 성부의 박 위치와 음 길이 순서로 발 음표의 자리를 맞춥니다. 동그라미 X(⊗)는 열린 하이햇, 작은 꾸밈음은 플램으로 읽습니다.
출판사마다 악기 위치 규칙이 조금 다르면 일부 악기가 바뀌어 나올 수 있으니 편집기에서 고쳐 주세요.
pdf.js(약 1.7MB)는 PDF를 처음 열 때만 불러옵니다.

### 그림으로 된 악보 (스캔·이미지 PDF)

글자 정보 없이 악보가 그림 한 장으로 들어 있는 PDF는 `omr.ts`가 그림에서 직접 기호를 찾아(간단한 광학 악보 인식) 위와 같은 글자·선분으로 바꾼 뒤 같은 방법으로 읽습니다.

1. 흑백으로 바꾸고, 페이지 폭 대부분을 가로지르는 줄 5개를 오선으로 찾은 뒤 오선을 지웁니다.
2. 오선 간격의 두 배보다 긴 가는 세로선 = 기둥·마디줄 (연한 회색 기둥도 찾습니다).
3. 남은 검은 덩어리를 크기·채움 정도·모양(X 대각선, ⊗ 테두리, 구멍, 갈고리)으로 나눕니다:
   꽉 찬 머리·X·⊗·괄호 친 고스트 노트, 빔(기운 빔·두 겹 빔 포함), 꼬리, 점, 쉼표, 강세(>), 열림(o), 마디 반복(%), 잇단음표 숫자(3·5·6).
   맞붙어 한 덩어리가 된 X 머리는 머리 폭으로 나누고, 기둥을 지울 때 갈라진 기호(괄호 친 머리, 작은 머리, 4분쉼표)는 다시 붙여 읽습니다.
4. 숫자는 여러 글꼴로 그린 0~9 견본(`digits.ts`, 가로 5 × 세로 7칸의 검은 정도)과 비교해 읽습니다.
   `♩ = 130`의 빠르기와 여러 마디 쉼표 막대 위의 마디 수를 읽습니다.
   박자표 숫자는 오선과 겹쳐 있어, 악보 글꼴(Bravura·Leland·Petaluma·Gonville) 숫자를 오선과 함께 그린 견본과 비교합니다.

정확도에는 한계가 있습니다. 해상도가 낮거나 기호가 겹친 곳에서는 음이 빠지거나 길이를 잘못 읽을 수 있고, 그런 마디는 음 위치로 박을 어림합니다.
빠르기 표시가 없거나 못 읽으면 BPM 100으로 시작합니다.

## 구조

```
악보(Score) ──► 타임라인(Timeline: 시간 + 손발 배정) ──┬─► Transport (Web Audio 소리 예약)
                                                    ├─► MotionPlanner ─► DrummerPose ─► DrummerRig (캐릭터)
                                                    └─► DrumKit (타격 피드백)
```

| 경로 | 역할 |
| --- | --- |
| `src/core/` | 악보 형식, 타임라인, 손발 배정(`sticking.ts`), 박 나눔 고르기(`grid.ts`), 예제 |
| `src/import/` | MIDI·드럼 탭·PDF 악보(`pdfPage.ts`: PDF 그리기 명령 → 글리프·선분, `sheet.ts`: 악보 해석·반복 펼치기, `omr.ts`·`digits.ts`: 그림 악보 인식) 가져오기, 음원 → 드럼 악보(`audio.ts`: 대역별 타격 검출·빠르기·박 찾기) |
| `src/audio/` | 오디오 엔진, 사운드 킷(`kits/`: 합성·샘플), 재생/예약 |
| `src/motion/` | 재생 위치 → 드러머 자세 계산 (상태 없음: 되감기·반복해도 소리와 항상 일치), 직접 연주 동작 덧씌우기 |
| `src/drummer/` | 캐릭터 리그 인터페이스와 기본 도형 캐릭터(2관절 IK) |
| `src/scene/` | 무대, 카메라, 드럼 세트 |
| `src/ui/` | PDF 악보 보기(`SheetView.ts`), 격자 악보 편집기, 드럼 패드 |

### 3D 모델 캐릭터 (glTF)

`src/drummer/GltfRig.ts`가 뼈대 있는 glTF 모델을 드러머로 만듭니다.
모델의 앉은 자세 애니메이션을 기본으로 두고, 매 프레임 팔·다리 뼈에 2관절 IK를, 머리 뼈에 시선을, 척추에 상체 기울기를 적용합니다.
2등신처럼 팔다리가 짧은 캐릭터는 `limbStretch`로 관절 사이만 늘리고, `seat`로 의자 높이·위치를 체형에 맞춥니다.
`scripts/prepare_models.mjs`는 KayKit 같은 모델에서 앉은 자세 하나만 남기고 무기를 빼서 용량을 줄이는 예시입니다.
지금 기본 캐릭터는 모두 도형으로 만든 것이라 `public/models`는 비어 있습니다.

### 새 캐릭터 추가하기

캐릭터는 `DrummerRig` 인터페이스(`src/drummer/DrummerRig.ts`)만 구현하면 됩니다.
리그는 매 프레임 `DrummerPose`(양손 스틱 끝 목표 위치, 들어 올린 높이, 양발 각도, 시선)를 받아
자기 몸에 맞게 IK로 풉니다. 자세가 관절 각도가 아니라 목표 위치라서 체형이 다른 캐릭터도 같은 모션을 씁니다.
`src/drummer/characters.ts`에 항목을 추가하면 캐릭터 선택 메뉴에 나타납니다.

## 로드맵

1. **캐릭터 더 만들기**: 도형 캐릭터(`ProceduralRig`)에 새 머리 모양을 추가하거나, 뼈대 있는 glTF 모델을 `GltfRig`로 붙이기
2. **악보 가져오기 확장**: MusicXML(악보 프로그램 내보내기), 사진으로 찍은 악보(기울어짐·휘어짐 보정)
3. **음원 드럼 분리 서버**: Demucs 같은 AI로 드럼만 분리한 뒤 악보로 바꿔 일반 곡에서도 정확도 높이기
4. 플램·롤 같은 주법, 더블 페달, 왼손잡이 세팅, 킷별 튜닝·믹서
